# The `.clip` file format (CLIP STUDIO FORMAT)

This is the complete record of what libclip knows about `.clip` files:
the byte layout, the database schema, the raster encoding, which rules Clip
Studio Paint actually enforces when loading, and what is still unknown.

**Evidence tags**

* **[observed]**: read directly from a file. Sources are the strings, code and tables of
  `CLIPStudioPaint.exe` 5.1.4 and `ClipPreview.dll`, and the reference document
  `yuzuko.clip`, saved by Clip Studio Paint 5.1 (1200×1600 px, one raster layer
  "Layer 1" plus "Paper").
* **[tested]**: confirmed by opening purpose-built files in Clip Studio Paint
  5.1 (see §8).
* **[inferred]**: a conclusion drawn from observations.
* **[unknown]**: not yet understood; see §10.

**Status.** libclip implements everything below. Its reader decodes the
reference document pixel-identically to CSP's own embedded preview
(1 920 000 of 1 920 000 pixels). Clip Studio Paint opens files written by
its writer, both round trips of CSP documents and documents created from
scratch **[tested, 2026-11-10]**. `examples/clipinfo.c` prints the container, canvas and layer
structures, and `clip_document_query()` exposes every table described here.

---

## 1. Overview

A `.clip` file is a **chunked container wrapping a SQLite database and a
set of raw binary blobs** **[observed]**:

```
CSFCHUNK header (24 bytes)
├─ CHNKHead   40 bytes: format version, offset of CHNKSQLi, document GUID
├─ CHNKExta   external blob, id "extrnlid" + 32 hex   ← tiles of one offscreen
├─ CHNKExta   …                                          (one chunk per stored offscreen)
├─ CHNKSQLi   complete SQLite 3 database image        ← all document structure
└─ CHNKFoot   empty
```

The database describes the document: canvas, layer tree, layer properties,
mipmaps, thumbnails, preview and a schema registry. Large binary values
(layer tiles, vector data, 3-D data) live in `CHNKExta` chunks. The database
refers to them by id.

Supporting evidence **[observed]**:

* The executable contains the literals `CSFCHUNK`, `CHNKHead`, `CHNKExta`,
  `CHNKSQLi`, `CHNKFoot`, `extrnlid`, `%s-journal` and `%s-wal` next to its
  SQLite code. SQLite 3.30.1 is linked statically.
* RTTI class names (`PWSQLiteVFS`, `PWDBSQLiteChunk`, `PWDBSQLiteChunkRead`,
  `PWDBBlobSQLite`) show that SQLite runs on a custom VFS that maps the
  `CHNKSQLi` payload onto the container.
* `ClipPreview.dll`, the Explorer preview handler, contains only `CSFCHUNK`,
  `CHNKHead` and `CHNKSQLi`. It reads the preview from a table and never
  touches external chunks.

## 2. Container byte layout

All container integers are **big-endian** **[observed]**.

### 2.1 File header

| Offset | Size | Field |
|---|---|---|
| 0 | 8 | magic `CSFCHUNK` |
| 8 | 8 | u64 total file size |
| 16 | 8 | u64 `24`, the size of this header |

### 2.2 Chunk framing

Chunks follow the header back to back until `CHNKFoot`.

| Size | Field |
|---|---|
| 4 | `CHNK` |
| 4 | tag: `Head`, `Exta`, `SQLi` or `Foot` |
| 8 | u64 payload size |
| n | payload |

The order observed in CSP files, and used by libclip, is `Head`, then
all `Exta` chunks, then `SQLi`, then `Foot`.

### 2.3 `CHNKHead` payload (40 bytes)

| Offset | Size | Field |
|---|---|---|
| 0 | 8 | u64 format version, `0x100` |
| 8 | 8 | **u64 file offset of the `CHNKSQLi` chunk** (offset of its `CHNK` tag) |
| 16 | 8 | u64 `16`, the length of the GUID that follows |
| 24 | 16 | document GUID |

CSP's container reader is a function around `0x143B48700` in
`CLIPStudioPaint.exe`. It runs these checks in order **[observed]**:

1. The magic is `CSFCHUNK`.
2. The first chunk tag is `CHNKHead`.
3. The `Head` payload is at least `0x28` bytes.
4. `(version & 0xFF00) <= 0x100`.
5. The GUID length is exactly 16.
6. It seeks to the stored `CHNKSQLi` offset and checks that the 8 bytes there read `CHNKSQLi`.

Any failure makes CSP report **"Unsupported file format"** **[tested]**. In
the reference file the offset is 657 933 (`0x0A0A0D`). It is not a constant.
The GUID's value is not checked: files with a GUID generated by libclip
open **[tested]**.

### 2.4 `CHNKExta` payload

| Size | Field |
|---|---|
| 8 | u64 id length, 40 |
| 40 | id: `extrnlid` + 32 upper-case hex digits (ASCII) |
| 8 | u64 data length |
| n | data: for raster offscreens, the tile stream of §5.2 |

CSP's ids look like GUIDs without dashes. Any 32 hex digits are accepted
**[tested]**.

### 2.5 `CHNKSQLi` and `CHNKFoot`

`SQLi` is a complete SQLite database image with 4096-byte pages, UTF-8, schema
format 4. `Foot` has an empty payload. The SQLite header's change counter and
version fields are not checked: zeros, as written by `sqlite3_serialize`,
are accepted **[tested]**.

## 3. External chunk bookkeeping

Three tables tie database values to `CHNKExta` chunks. Their SQL is embedded
in the executable verbatim **[observed]**:

```sql
CREATE TABLE IF NOT EXISTS ExternalTableAndColumnName(TableName TEXT, ColumnName TEXT);
CREATE TABLE IF NOT EXISTS ExternalChunk(ExternalID BLOB, Offset INTEGER);
CREATE TABLE IF NOT EXISTS RemovedExternal(ExternalID BLOB);
SELECT Offset FROM ExternalChunk WHERE ExternalID='%s';
```

* **`ExternalTableAndColumnName`** lists the columns that hold external ids.
  A 5.1 document has ten rows: `Offscreen.BlockData`,
  `VectorObjectList.VectorData`, `Canvas3DModelBank.BankData`,
  `Canvas3DModelLoader.ModelData`, `Track.TrackActionMixer`,
  `Track.TrackActionMixer2`, `CanvasItemBinary.ItemBinaryData`,
  `Manager3DOd.SceneData`, `ModelData3D.Layer3DModelData` and
  `TimeLapseBlob.BlobData`.
* **`ExternalChunk`** maps each id to the file offset of its `CHNKExta` chunk
  (the offset of the `CHNK` tag).
  * **Important:** `ExternalID` must hold **TEXT** values, even though the
    column is declared `BLOB`. CSP looks chunks up with the query above, and
    SQLite never treats a BLOB as equal to a text literal. With BLOB-typed
    ids every lookup misses, and CSP reports "Layer 1: Part of image failed
    to be imported because layer image or layer mask was corrupted"
    **[tested]**.
  * By contrast, `Offscreen.BlockData` holds the same id as a **BLOB**
    **[observed]**.
* **`RemovedExternal`** collects ids whose rows were updated or deleted, so
  their chunks can be dropped on the next save. CSP creates one pair of
  triggers per external column. The `Offscreen` pair is:

  ```sql
  CREATE TRIGGER ExternalUpdateOfBlockDataOnOffscreen UPDATE OF BlockData ON Offscreen
      BEGIN INSERT INTO RemovedExternal(ExternalID) VALUES(OLD.BlockData); END;
  CREATE TRIGGER ExternalDeleteOfBlockDataOnOffscreen DELETE ON Offscreen
      BEGIN INSERT INTO RemovedExternal(ExternalID) VALUES(OLD.BlockData); END;
  ```

  The template in the executable is `ExternalUpdateOf^0%sOn^1%s …`.

## 4. Database schema

### 4.1 Conventions [observed]

* Every object table is created as
  `CREATE TABLE <T>(_PW_ID INTEGER PRIMARY KEY AUTOINCREMENT, MainId INTEGER DEFAULT NULL, …)`.
  It has an index `CREATE INDEX 'idx<T>' on <T>(MainId)`. Columns are added
  over time with `ALTER TABLE … ADD COLUMN`.
* **Rows refer to each other by `MainId`**, never by `_PW_ID`. A reference
  value of 0 means "none".
* **Schema registry.** Two tables describe the object model:
  * `ElemScheme(TableName, ElemType, MaxIndex)` has 61 rows, one per object
    table. `MaxIndex` is the highest `MainId` handed out.
  * `ParamScheme(TableName, LabelName, DataType, Flag, OwnerType, LockType,
    LockSpecified, AlternativeLockType, AlternativeLockSpecified, LinkTable)`
    has 1 165 rows, one per property. `DataType` is 1 = int, 2 = real,
    3 = text or 4 = blob. `LinkTable` names a referenced table, and is `''`
    when there is none.
  * `src/csp_schema_data.h` is generated from a CSP document by
    `gen/gen_csp_schema.py`. It carries the table definitions and
    both registry tables, so files written by libclip declare the same
    schema as CSP.
* **ID conventions in CSP files.** A layer's `Mipmap` and `LayerThumbnail`
  rows reuse the layer's `MainId`. `MainId`s of other tables have gaps. CSP
  does **not** require any of this **[tested]**.

A fresh 5.1 document has these 16 tables: `AnimationCutBank`, `Canvas`,
`CanvasItem`, `CanvasItemBank`, `CanvasPreview`, `ElemScheme`,
`ExternalChunk`, `ExternalTableAndColumnName`, `Layer`, `LayerThumbnail`,
`Mipmap`, `MipmapInfo`, `Offscreen`, `ParamScheme`, `Project` and
`RemovedExternal`.

Other table names appear in the executable and the registry but not in a
fresh document. Examples: `CanvasNode`, `LayerObject`, `VectorObjectList`,
`BrushStyle`, `BrushPatternImage`, `Material`, `MaterialThumbnail`, `Track`,
`TimeLine`, `TimeLapseBlob` and `ModelInfo3D`.

### 4.2 Object graph

```
Project ── ProjectCanvas ──▶ Canvas
Canvas  ── CanvasRootFolder ──▶ Layer (root folder)
Layer   ── LayerFirstChildIndex / LayerNextIndex ──▶ Layer          (tree)
        ── LayerRenderMipmap ──▶ Mipmap ── BaseMipmapInfo ──▶ MipmapInfo (100 %)
                                              MipmapInfo ── NextIndex ──▶ MipmapInfo (50 %, 25 %, …)
                                              MipmapInfo ── Offscreen ──▶ Offscreen ── BlockData ──▶ CHNKExta
        ── LayerLayerMaskMipmap ──▶ Mipmap (same structure, mask)
        ── LayerRenderThumbnail ──▶ LayerThumbnail ── ThumbnailOffscreen ──▶ Offscreen (512×512)
```

### 4.3 `Canvas` (one row)

* `CanvasUnit`: 0 = pixels.
* `CanvasWidth`, `CanvasHeight`: REAL, in the unit.
* `CanvasResolution`: REAL, dpi.
* `CanvasChannelBytes`: 1 for 8-bit.
* `CanvasDefaultChannelOrder`: 33 for 8-bit BGRA with a separate alpha
  plane, the same value as the tiles' `BlockDataChannelOrder`.
* `CanvasRootFolder`: `MainId` of the invisible root folder layer.
* `CanvasCurrentLayer`: `MainId` of the selected layer.
* Other columns hold colour management (`CanvasSrcProfile*`,
  `CanvasDstProfile*`, `CanvasSimulate*`, `CanvasRenderingIntent`),
  defaults (`CanvasDefaultColorTypeIndex`, `CanvasDefaultToneLine`), comic
  layout (`ComicStory*`, `ComicBindPosition`, `CropFrameShow`) and 3-D
  (`Canvas3DModelDataLoaderIndex`, 2).

### 4.4 `Layer`

Column order as CSP creates it **[observed]**:

```
MainId CanvasId LayerName LayerType LayerLock LayerClip LayerMasking
LayerOffsetX LayerOffsetY LayerRenderOffscrOffsetX LayerRenderOffscrOffsetY
LayerMaskOffsetX LayerMaskOffsetY LayerMaskOffscrOffsetX LayerMaskOffscrOffsetY
LayerOpacity LayerComposite LayerUsePaletteColor LayerNoticeablePaletteColor
LayerPaletteRed LayerPaletteGreen LayerPaletteBlue LayerFolder LayerVisibility LayerSelect
LayerNextIndex LayerFirstChildIndex LayerUuid
LayerRenderMipmap LayerLayerMaskMipmap LayerRenderThumbnail LayerLayerMaskThumbnail
UsePreviewColorType UsePreviewMaskColorType EffectRangeType DraftLayer FilterLayerV132
DrawColorMainRed DrawColorMainGreen DrawColorMainBlue DrawColorEnable
DrawToRenderOffscreenType SpecialRenderType DrawToRenderMipmapType MoveOffsetAndExpandType
FixOffsetAndExpandType RenderBoundForLayerMoveType SetRenderThumbnailInfoType
DrawRenderThumbnailType MonochromeFillInfo
LayerColorTypeIndex LayerColorTypeBlackChecked LayerColorTypeWhiteChecked
```

**Tree** **[observed]**

* The root folder has an empty name, `LayerType` 256, `LayerFolder` 1 and
  `LayerMasking` 32.
* **`LayerFirstChildIndex` points to the BOTTOM-most child.
  `LayerNextIndex` points to the sibling ABOVE it.** 0 ends a list.
* So, to get the order shown in CSP's Layer palette, collect each sibling
  list and reverse it.
* In the reference file the root's first child is the Paper layer, and the
  Paper's `NextIndex` is Layer 1.

**`LayerType`** is a bit set **[observed]**:

| Value | Meaning |
|---|---|
| `0x001` (1) | raster image layer |
| `0x100` (256) | folder (the root folder is exactly 256) |
| `0x630` (1584) | Paper fill layer |

Other kinds (vector, text, gradient, 3-D, tone, adjustment) were not in the
reference file **[unknown]**.

**Compositing**

* `LayerOpacity`: 0…256, where 256 = 100 % **[observed]**.
* `LayerComposite`: blend mode index, 0 = Normal **[observed]**. libclip
  maps the other values from the order of CSP's blend-mode menu
  **[inferred, untested]**.
* `LayerClip`: 1 = clip to the layer below.
* `LayerVisibility`, `LayerLock`, and `LayerSelect`, which is 1 on the
  selected layer.
* `LayerMasking`: 32 on the root folder, 0 on ordinary layers
  **[unknown meaning]**.

**Geometry** **[observed]**

* `LayerOffsetX/Y` is the layer's origin on the canvas.
  `LayerRenderOffscrOffsetX/Y` is the origin of its render offscreen
  relative to that. All four are 0 for a default layer.
* A raster layer's offscreen covers whole 256-pixel blocks, and **may extend
  beyond the canvas**. The reference layer's offscreen is 1280×2048 on a
  1200×1600 canvas, because strokes run past the bottom edge.
* Offscreens padded only to the canvas, such as 1280×1792 here, are accepted
  **[tested]**.
* The root folder's and Paper's offscreens are exactly canvas-sized
  (1200×1600).

**Paper layer** **[observed]**

* `DrawColorEnable` = 1.
* `DrawColorMainRed/Green/Blue`: each 0xFFFFFFFF for white.
* `SpecialRenderType` = 20 and `DrawToRenderOffscreenType` = 61.
* `DrawToRenderMipmapType`, `MoveOffsetAndExpandType`, `FixOffsetAndExpandType`,
  `RenderBoundForLayerMoveType`, `SetRenderThumbnailInfoType` and
  `DrawRenderThumbnailType` are each 31.
* `MonochromeFillInfo` is a 62-byte blob:
  `u32 62, u32 1, ustr "MonochromeSetting", u32 0, 0, 0, 1` (ustr: §5).
* The Paper's offscreens have no stored tiles. CSP draws the fill colour.

**Other columns**

* `LayerUuid`: 32 lower-case hex digits grouped 10-4-4-4-10. Any such value
  is accepted **[tested]**.
* `LayerColorType*` appear on raster layers only.

#### 4.4.1 Layer Property effects [observed]

Surveyed over 693 CSP-saved files (10 000+ layer rows).

* **Expression color**: `LayerColorTypeIndex` 0 = Color, 1 = Gray,
  2 = Monochrome. `LayerColorTypeBlackChecked/WhiteChecked` are the
  Monochrome "black/white" toggles; libclip writes 1/1. The index also sets
  the storage of **every mipmap level**: Color uses channel order 33
  (alpha + BGRx, §5.3), Gray uses channel order 17 with packing
  `17 1 1 2 65536 1 256 1 256 65536 256 256 8 8 0 0`: a tile inflates to an
  alpha plane followed by one gray plane (2 bytes/px). Gray is 0 under
  transparent pixels. Monochrome uses a 1-bit packing (`17 1 1 1 8192 …`)
  that libclip does not write. The layer thumbnail stays order 33.
* **Layer color**: `LayerUsePaletteColor` 1 enables it;
  `LayerPaletteRed/Green/Blue` hold the colour with the 8-bit value repeated
  in all four bytes (`0x78787878`; white is `0xFFFFFFFF`).
  `LayerNoticeablePaletteColor` was 0 in every file.
* **`LayerEffectAttached INTEGER DEFAULT NULL`, `LayerEffectInfo BLOB
  DEFAULT NULL`** are **not** in the base `Layer` table: CSP appends this
  pair with `ALTER TABLE` the first time a layer in the document gets an
  effect (70 of 639 surveyed files). `LayerEffectAttached` is 1 next to a
  blob (or NULL in older files); both are NULL on layers whose effects were
  never touched. The `ParamScheme` row for `LayerEffectInfo` is always
  present.
* **`LayerEffectInfo`**: Always **610, 602 or 598 bytes**, version 2:

  ```
  u32 totalSize, u32 2
  ustr "EffectEdge"          24-byte payload (no size word)
  ustr "EffectTone"          76 bytes      ┐
  ustr "EffectTextureMap"    16 bytes      │ each payload starts with its
  ustr "EffectApplyOpacity"   8 bytes      │ own u32 size (except where
  ustr "EffectToneAreaColor" 16 bytes      │ noted)
  ustr "EffectTonePosterize" 28 bytes      │
  ustr "EffectWaterEdge"     40 bytes      │
  ustr "EffectLine"          116 bytes + 0/4/12-byte tail (CSP version) ┘
  ```

  The **border effect** is `EffectEdge`: `u32 enabled`, `f64 width` in
  pixels (e.g. 3.0, 1.0, 7.09), then `u32 red, green, blue` with the byte
  repeated in all four bytes. The other sections hold the tone, watercolor
  edge and line-extraction settings, whose layouts are **[unknown]**.
  libclip writes the 610-byte blob that CSP most often wrote for a layer
  with a border, patching only `EffectEdge`, and writes NULL when the border
  is off. Whether CSP opens such files is **[untested]**.

### 4.5 `Mipmap`, `MipmapInfo`, `Offscreen`

* `Mipmap(MainId, CanvasId, LayerId, MipmapCount, BaseMipmapInfo)`:
  `MipmapCount` is 5.
* `MipmapInfo(MainId, CanvasId, LayerId, ThisScale REAL, Offscreen, NextIndex)`:
  `ThisScale` is a percentage, 100, 50, 25, 12.5 or 6.25. `NextIndex` links
  to the next smaller level, and is 0 after 6.25.
* `Offscreen(MainId, CanvasId, LayerId, Attribute BLOB, BlockData BLOB)`:
  `Attribute` is described in §5.1. `BlockData` is the 40-byte external id,
  as a BLOB.

**Which offscreens have a `CHNKExta` chunk** **[observed]**

* The **base (100 %) level of a layer with pixels** has one.
* The **512×512 thumbnail offscreens** have one.
* The smaller mipmap levels, and the base levels of the Paper and the root
  folder, have none. Their `BlockData` names an id that is absent from the
  file, and CSP regenerates them on load.

The smaller levels' dimensions halve the base level's each time, for example
1280×2048, 640×1024, 320×512 and so on. Their `BlockSize` tables
(§5.1) may list real or empty sizes. CSP accepts mismatched sizes for these
regenerated levels **[tested]**.

### 4.6 `LayerThumbnail` [observed]

* Key columns: `MainId`, `CanvasId`, `LayerId`, `ThumbnailOffscreen` (a
  512×512 `Offscreen`), `ThumbnailCanvasWidth/Height`, `ThumbnailFixMode`
  (-1 for normal layers, 0 for the Paper) and `ThumbnailUseDrawColor` with
  `ThumbnailMainColor*` (1 and white for the Paper).
* Also: 14 `Thumbnail*NeedRefresh*` counters, plus colour-type and
  preview-mask flags.
* The counters look like change stamps (176474, 175572 and 14 in the
  reference file) **[unknown meaning]**.
* In CSP files only tile 0 of the thumbnail offscreen carries pixels: the
  drawing is scaled into its corner. All four tiles have `BlockStatus` 1.
* CSP accepts other thumbnail contents, other status values and counter
  value 1 **[tested]**.

### 4.7 `CanvasPreview`, `Project`, banks [observed]

* **`CanvasPreview(MainId, CanvasId, ImageType, ImageWidth, ImageHeight, ImageData)`**:
  `ImageType` is 1 and `ImageData` is a **full-size PNG** of the flattened
  canvas. This is what Explorer's preview pane shows. Any valid PNG is
  accepted **[tested]**.
* **`Project`**, one row:
  * `ProjectInternalVersion` is `'1.1.0'`.
  * `ProjectName`, `ProjectCanvas` (1), `ProjectItemBank` (1),
    `ProjectCutBank` (2) and `ProjectRootCanvasNode` (0).
  * `ComicStory*` story settings.
  * `DefaultPage*` page defaults. CSP stored `DefaultPageWidth/Height`
    swapped relative to the canvas. Either order is accepted **[tested]**.
* **Banks:** `CanvasItemBank(MainId 1, ModelBankMainIndex 0, BankRootItemMainIndex 0)`
  and `AnimationCutBank(MainId 2, FirstTimeLine 0, FirstScenario 0,
  CurrentIndex 0, Enable 0)` each have one row. `CanvasItem` exists but is
  empty.

## 5. Raster data

The blobs in this section are big-endian. A **ustr** is a `u32` character
count followed by UTF-16BE code units **[observed]**.

### 5.1 `Offscreen.Attribute`

```
u32 headerSize            16
u32 parameterSectionSize  102
u32 initColorSectionSize  42  (58 when InitColor carries image values)
u32 blockSizeSectionSize  34 + 4 × blockCount

ustr "Parameter"
u32 VOffscreenWidth
u32 VOffscreenHeight
u32 VOffscreenHorizontalBlockCount   ceil(width / 256)
u32 VOffscreenVerticalBlockCount     ceil(height / 256)
u32 × 16 packing values (8-bit RGBA):
    BlockDataChannelOrder           33
    BlockDataChannelBytes           1
    BlockDataChannelImageCount      4
    BlockDataPixelBytes             5     (1 alpha + 4 image)
    BlockDataOffsetImageBlockBytes  65536
    BlockDataOffsetImagePixelBytes  4
    BlockDataOffsetImageRowBytes    1024
    BlockDataOffsetAlphaPixelBytes  1
    BlockDataOffsetAlphaRowBytes    256
    BlockDataOffsetImageBlock       65536 (byte offset of the image plane)
    BlockDataHorizontalBlockWide    256
    BlockDataVerticalBlockWide      256
    BlockDataHorizontalBlockShift   8
    BlockDataVerticalBlockShift     8
    reserved                        0, 0

ustr "InitColor"
u32 20
u32 InitColorDataDoInitialize      0  (Paper: 1)
u32 InitColorDataAlphaValue        0  (Paper: 0xFFFFFFFF)
u32 InitColorDataImageValueCount   0  (Paper: 4)
u32 4
u32 × count InitColorDataImageValue   (Paper: 0, 0, 0, 0)

ustr "BlockSize"
u32 12
u32 blockCount
u32 4
u32 × blockCount    byte size of each block record in the tile stream (§5.2)
```

The names of the 16 packing values follow the order of the `VOffscreen`
rows in `ParamScheme`, which matches the string order in the executable.
The meaning of the two reserved words is **[unknown]**.

### 5.2 Tile stream (`CHNKExta` data)

Blocks are stored in row-major order, `blockIndex = by × blocksX + bx`,
followed by two trailer sections **[observed]**:

```
repeat blockCount times:
    u32  blockSize            bytes from this word to the end of the end marker
    ustr "BlockDataBeginChunk"
    u32  blockIndex
    u32  uncompressedSize     327680  (256 × 256 × 5)
    u32  blockWidth           256
    u32  blockHeight          256
    u32  hasData              0 = fully transparent, nothing follows
    if hasData:
        u32  payloadSize      zlibSize + 4                 (big-endian)
        u32  zlibSize                                       (LITTLE-endian)
        byte zlib stream      inflates to uncompressedSize bytes
    ustr "BlockDataEndChunk"

ustr "BlockStatus"    u32 12, u32 blockCount, u32 4, u32 × blockCount
ustr "BlockCheckSum"  u32 12, u32 blockCount, u32 4, u32 × blockCount
```

* **Compression.** Any valid zlib stream is accepted: stored (level 0)
  blocks, or fully compressed ones **[tested]**.
* **`BlockCheckSum`** is the **Adler-32 of the stored payload**: the 4-byte
  little-endian `zlibSize` followed by the zlib stream. It is 0 for blocks
  without data.
  * Found in CSP's tile serialiser (`0x14343E910`). That code passes this
    buffer to a helper at `0x143416030`, which uses the zlib idiom
    `f(f(0, NULL, 0), buf, len)` **[observed]**.
  * Matches all 36 stored blocks of the reference file **[observed]**.
  * CSP verifies it on load **[tested]**.
* **`BlockStatus`** is 0 for every block of a drawing layer and 1 for the
  thumbnail offscreens. Its meaning is **[unknown]**. Writing 0 everywhere
  is accepted **[tested]**.

### 5.3 Inflated tile layout (8-bit RGBA)

| Offset | Size | Content |
|---|---|---|
| 0 | 65 536 | alpha plane: 1 byte per pixel, 256 bytes per row |
| 65 536 | 262 144 | image plane: 4 bytes per pixel, **B, G, R, 255**, 1 024 bytes per row |

* Colour is **straight** (not premultiplied) **[observed]**.
* **The 4th image byte must be 255.** Tiles with 0 there are rejected as
  "layer image … corrupted", even when every checksum is valid
  **[tested]**.
* Never-painted pixels (alpha 0) have white colour. Pixels that were painted
  and then erased keep their old colour under alpha 0 **[observed]**. That
  colour is never displayed. Writing white for all alpha-0 pixels is
  accepted **[tested]**.
* The padding area beyond the image edge inside a tile is likewise
  alpha 0 with white colour **[observed]**.

## 6. What Clip Studio Paint enforces on load

Every row below was settled by opening purpose-built files in Clip Studio
Paint 5.1 (§8).

**Enforced** (a violation makes the file fail to open, or drops the layer image):

| Rule | Symptom when broken |
|---|---|
| `CHNKHead` offset points at the `CHNKSQLi` chunk (§2.3) | "Unsupported file format" |
| `CHNKHead` version check and GUID length 16 (§2.3) | "Unsupported file format" **[observed in code]** |
| `ExternalChunk.ExternalID` stored as TEXT (§3) | "Layer 1: Part of image failed to be imported because layer image or layer mask was corrupted" |
| `BlockCheckSum` = Adler-32 of the stored payload (§5.2) | same as above |
| 4th image byte = 255 (§5.3) | same as above |

**Not checked** (any value tried was accepted):

* **Container:** the document GUID; the external id values.
* **Tile encoding:** the zlib compression level; `BlockStatus`.
* **Database storage:** the SQLite header's change-counter and version
  fields; the row insertion order of every table.
* **Rows and IDs:** `MainId` numbering, including whether `Mipmap` and
  `LayerThumbnail` ids equal their layer's id; `ElemScheme.MaxIndex`;
  `LayerUuid` values.
* **Regenerated data:** the dimensions and `BlockSize` tables of
  regenerated mipmap levels; thumbnail contents and refresh counters.
* **Preview and project:** the `CanvasPreview` image; `Project.DefaultPage*`.

## 7. Reading and writing (as implemented in libclip)

**Reading**

1. Parse the chunks. Load `CHNKSQLi` with `sqlite3_deserialize`, read-only
   and in memory.
2. Read `Canvas`, then all `Layer` rows. Walk the tree from
   `CanvasRootFolder`, reversing sibling lists to get palette order.
3. For each raster layer, follow `LayerRenderMipmap`, then `BaseMipmapInfo`,
   then `Offscreen`. Parse the `Attribute`. Find the chunk whose id equals
   `BlockData`. Inflate each block and place it at
   `(index mod blocksX, index div blocksX) × 256`.
4. Position the result at `LayerOffset + LayerRenderOffscrOffset`. Apply the
   mask mipmap if one is present. Composite with `LayerComposite` and
   `LayerOpacity`. The Paper layer becomes the document's paper colour.
5. Verify each block's `BlockCheckSum`, and count mismatches
   (`clip_offscreen_data.checksum_mismatches`).

Limitation: layers are cropped to the canvas, so content beyond the canvas
edge is dropped on a round trip.

**Writing** (`src/clip_writer.c`)

* Create CSP's 16 tables, 9 indexes and the `Offscreen` triggers, with the
  `ElemScheme`/`ParamScheme` registry.
* Write a root folder, an optional Paper layer, and for each raster layer:
  * a 5-level mipmap chain, with tiles stored for the base level only;
  * a 512×512 thumbnail offscreen;
  * `Layer` and `LayerThumbnail` rows with CSP's default values.
* Compress tiles with libclip's own DEFLATE encoder
  (`src/clip_zlib.c`, level 6) and compute `BlockCheckSum`.
* Write `ExternalChunk` ids as TEXT, with offsets computed before the
  database is serialised: header (24 B) + `CHNKHead` (56 B) + preceding
  chunks.
* Patch the `CHNKSQLi` offset into `CHNKHead` and the file size into the
  header.

A round trip of the reference document is about half the size of CSP's
original. Both CSP and libclip's reader open it.

## 8. How these facts were established

* **Static analysis** of the shipped binaries: import, export and string
  tables, RTTI names, and disassembly with `dumpbin`. Code addresses refer to
  `CLIPStudioPaint.exe` 5.1.4 (SHA-256 `14c5f8ab…a1d5607facf5`).
* **The reference document** `yuzuko.clip`, decoded with libclip's reader and
  compared against CSP's embedded preview.
* **A preview probe**: a small program that loads CSP's `ClipPreview.dll` and reports
  whether it draws a file. It only exercises the container and
  `CanvasPreview`, so it cannot detect tile or bookkeeping errors.
* **Bisection in Clip Studio Paint.** Hybrid files were made by applying one
  difference at a time between libclip's writer and the reference
  document. CSP's verdict on each produced the tables in §6.

## 9. Pitfalls for implementers

* Mixed byte order: the payload length before each zlib stream is
  big-endian, and the zlib length right after it is little-endian.
* `ExternalChunk.ExternalID` must be TEXT, but `Offscreen.BlockData` is a
  BLOB.
* The layer list is linked bottom-up.
* The `CHNKHead` field that looks like a constant is a file offset.
* The image plane has 4 bytes per pixel, and the 4th must be 255.
* A layer's offscreen can be larger than the canvas.

## 10. Unknowns and open questions

* **Layer effects:** the payloads of `EffectTone`, `EffectWaterEdge`,
  `EffectLine` and the other non-border sections of `LayerEffectInfo`.
* **Layer kinds:** `LayerType` values for vector, text, gradient, tone,
  adjustment and 3-D layers; the formats of `VectorObjectList.VectorData`
  and the other external columns.
* **Layer masks:** `LayerLayerMaskMipmap` should follow §5. The mask tile
  layout (likely alpha-only) has not been seen in a real file.
* **Other colour modes:** the 1-bit monochrome packing (§4.4.1) and
  16-bit and CMYK channel orders, and `CanvasUnit` values other than 0.
* **Blend modes:** the `LayerComposite` numbering beyond 0 = Normal.
* **Unexplained fields:** `BlockStatus`, `LayerMasking` (32 on the root),
  the `Thumbnail*NeedRefresh*` counters, the two reserved packing words, the
  constants `20` and `4` in the InitColor section, and `12`/`4` in the
  BlockSize and trailer headers.
* **Multi-page documents:** folders other than the root, animation cels,
  and multi-page `.cmc` projects.
